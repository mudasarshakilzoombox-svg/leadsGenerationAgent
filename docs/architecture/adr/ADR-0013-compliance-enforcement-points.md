# ADR-0013: Compliance enforced at import, enrollment and send. Country policy

- **Status:** Proposed · **Date:** 2026-11-26 · **Maps to:** AD-13, AD-22

## Context
CAN-SPAM, GDPR/UK GDPR/PECR, CASL, the Australian Spam Act and mailbox-provider sender rules require opt-out handling, identification and lawful targeting. A single check point misses state changes (for example, an unsubscribe after enrollment).

## Decision
- Suppression and eligibility are checked at **three** points: import or discovery (before paying), enrollment, and **immediately before every send** (`SendPolicy`).
- RFC 8058 one-click unsubscribe plus a visible link and identification footer are generated by code, never by AI.
- `CountryPolicy` with launch defaults: US, GB, IE, CA, AU allowed (with the CA/AU implied-consent attestation), strict-consent countries blocked without consent, and others (including unknown) warn with Admin attestation (SECURITY.md §10.2).
- Platform kill switches (global, workspace, mailbox) are implemented by pausing queues and `SendPolicy` SP-02.

## Alternatives considered
- **Check only at enrollment:** misses late unsubscribes and bounces.
- **Block all non-launch countries:** safer but too restrictive for customers. Warning + attestation keeps responsibility explicit.

## Consequences
- ➕ Opt-outs honored immediately. A clear audit trail of attestations.
- ➖ More checks per send (cheap indexed lookups).

## Verification
`SendPolicy` unit tests per check, Gate 2 compliance review, counsel review of the country table before launch.
