# ADR-0020: UUIDv7 primary keys

- **Status:** Proposed · **Date:** 2026-11-26

## Context
IDs appear in URLs and must not be enumerable. Sequential integers leak volume and invite IDOR probing. Random UUIDv4 fragments B-tree indexes on high-insert tables (`email_events`, `ai_runs`, `usage_records`).

## Decision
All primary keys are UUIDv7, generated by Prisma `@default(uuid(7))` or in application code where an ID is needed before insert (for example, deterministic `Message-ID` composition). Join tables use composite primary keys.

## Alternatives considered
- **bigint identity:** compact and fast, but enumerable and leaks business volume.
- **UUIDv4:** not enumerable, but poor index locality.
- **ULID/CUID2:** similar properties, but non-native types.

## Consequences
- ➕ Time-ordered inserts (good index locality). Non-guessable. Native `uuid` type.
- ➖ The 128-bit keys are larger than bigint (acceptable). The embedded timestamp reveals creation time (acceptable, it isn't sensitive).

## Verification
Schema lint: every model `id` is `@db.Uuid @default(uuid(7))`.
